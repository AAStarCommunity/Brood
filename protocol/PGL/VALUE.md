## 三大用户价值支柱

### 支柱一 · 消除信息差（Discovery）

**问题**：GitHub 上有几十万个免费的优质 AI 工具 —— 电子宠物、PDF 扫描、PPT 生成、本地翻译、知识库问答 —— 但普通人**根本不知道这些东西的存在**，更不会去 clone repo。

**我们怎么解**：
- 把这些开源公物**主动策展、分类、可搜索**地放进商店
- 标准化的中文介绍 + 截图 + 演示视频
- 推荐算法基于真实使用留存（不是广告竞价）
- 一句话告诉用户「这能干嘛」，而不是要你读 README

**一句话**：「我朋友圈刷不到的好工具，AgentStore 帮我找到。」

---

### 支柱二 · 抹平 UX Gap（Usability）

**问题**：开发者口中的"易用"和普通用户的"易用"差三个数量级。在 GitHub 上「`pnpm install && pnpm dev`」对开发者是"易用"，对普通用户是天书。

**我们怎么解**：
- **强制 PGL UI Module 规范**：作者上架必须提供一键能用的界面
- **统一一键安装**：Docker / 浏览器 iframe 沙箱 / Agent24 内嵌，背后差异用户感知不到
- **统一登录态**：用 AirAccount passkey（指纹/面容）一次登录所有作品
- **统一付费体验**：xPNTs 余额、一次确认、SuperPaymaster 赞助 Gas
- **错误友好化**：把容器启动失败翻译成"网络不太好，重试一下"

**一句话**：「我妈也能用，不用我打电话教。」

> 这一条不是口号 —— 我们把它做成上架的硬验收标准，叫 **「妈妈测试」**。
> 任何作品上架前，必须经过"递给妈妈用 3 分钟"的真实测试。详见 [`ONBOARDING.md`](./ONBOARDING.md#45-上架前的硬性验收妈妈测试--mother-test)。

### 支柱三 · Local-First（Token-Free + Privacy）

**问题**：OpenAI / Claude / Gemini 的 GPTs 都很强，但：
- 你的数据全部上传到他们服务器
- 每次调用都在烧 token（订阅 + 用量都不便宜）
- 模型随时被下架、改价、限速，你的工作流随时断
- 中国大陆用户还有访问门槛

**我们怎么解**：

**Local-first ≠ Local-only**。我们的设计原则是：

| 数据/任务类型 | 默认路由 | 用户可改 |
|:---|:---|:---|
| 个人敏感数据（身份、私信、健康、财务） | **本地推理** | 不允许走远程 |
| 一般个人数据（笔记、文档、照片） | **本地优先** | 用户可选远程（更快/更强模型） |
| 已脱敏数据（去掉 PII 后的文本/向量） | 本地 or 远程 | 用户/作者声明 |
| 公开数据（公文、新闻、共享知识） | **任意** | 自由选择 |
| 重模型场景（视频生成、超大模型推理） | **远程为主** | 但可选本地（如机器够强） |

具体能力：
- **优先使用本地模型**（M1 Mac / Linux / Windows / 边缘设备都行）
- 个人敏感数据**默认不出本地**
- 用户/作者可在 `pgl.yml` 的 `compliance.data_processed` 中**显式声明**哪类数据走哪条路径
- **零 Token 成本**（用本地推理 = 用电而已）
- 远程不是被禁止，是**second option**：脱敏后或公开数据可用 SuperPaymaster 赞助调用远程
- 与 iDoris、MOSS-TTS-Nano、Wan2.1 等开源本地模型生态深度集成

**一句话**：「敏感的留在本机，公开的用最快通道，全程我自己说了算。」

### 附加价值 · 公允回流（Trust）

**问题**：你在淘宝买一个"AI 模型工具"，原作者一分钱拿不到，还可能被抹了署名。你的钱去到了套利者口袋。

**我们怎么解**：
- 公约强制三角色分账 + 链上自动结算（**Supplier 50-90% / Wrapper 0-40% / Seller 固定 10%**）
- 所有销售记录链上可查，谁拿了多少钱透明
- 你付的每一块钱，**至少 90% 流向真正普惠普通个体的创造者和建设者**（Supplier 50-90% + Wrapper 0-40%）

**一句话**：「我花的钱，是给真正服务普通人的创造者和建设者，不是中间商。」

## 三大用户层级

### 层级一 · 个体（Individuals）

**他们是谁**：
- 时间紧、预算少、隐私敏感
- 有具体场景化诉求：考试复习、PDF 整理、写作助手、电子宠物陪伴、相册整理、视频剪辑
- 不会 git，不会 Python，但会用 App

**他们能从 AgentStore 得到什么**：

| 诉求 | AgentStore 给的 |
|:---|:---|
| 找到合适的小工具 | 中文策展 + 真实评分 |
| 不会装 / 不敢装 | 一键安装 + 沙箱保护 |
| 不想交订阅费 | 本地优先 + 一次付费选项 |
| 不想数据被采集 | Local-first 默认 |

---

### 层级二 · 中小组织 / SMEs

**他们是谁**：
- 5~50 人的律所、设计工作室、医疗诊所、教培机构、独立电商
- 有明确业务痛点（合同审查、客户服务、内容生产）但雇不起开发团队
- 用 SaaS 又怕数据合规问题

**他们能从 AgentStore 得到什么**：

| 诉求 | AgentStore 给的 |
|:---|:---|
| 行业专用 agent（法律 / 医疗 / 教育） | 公物市场已存或可委托社区改造 |
| 自部署 + 数据合规 | Docker / 本地部署模式 |
| 团队多账号管理 | 组织级 AirAccount + 角色权限（复用 SuperPaymaster v5 角色体系） |
| 财务报销支持 | xPNTs / USDC 都可换发票 |

**杀手级场景**：一家律所发现一个「合同条款比对 + 风险标记」的开源 agent，签 PGL 后委托社区做 UI 封装 → 全所一周内用上 → 月费比 SaaS 低一个数量级。

---

### 层级三 · 城市 / CityOS

**他们是谁**：
- 地方政府、城市治理者、社区组织
- 想用 AI 提升公共服务效率（市民问询、办事指南、文化传播）
- 但被「采购大厂方案 → 黑盒 → 高价 → 数据出境」困住

**他们能从 AgentStore 得到什么**：

| 诉求 | AgentStore 给的 |
|:---|:---|
| 公共服务 agent 池 | 开源公物 + 城市定制改造 |
| 城市数据不出境 | Local-first 架构原生支持 |
| 建立城市数字声誉 | 网络效应 — 公物 + 用户构成的 reputation 网络 |
| 透明的预算流向 | 链上付费记录可审计 |

**与 CityOS 的关系**：当一个城市基于 AgentStore 部署了几十个本地化公共服务 agent，并通过 OpenPNTs 积分系统记录市民参与，**这个城市就在 Mycelium 网络上拥有了一个可验证的"数字治理声誉"**。这是 Mycelium CityOS 协议的天然落地路径。

## 与 PGL Charter 的关系

支柱三（Local-first）和附加价值（公允回流）的实现依赖 Charter：

- Charter 第一条「可访问性承诺」→ 支柱一（消除信息差）
- Charter + UI Module Spec → 支柱二（抹平 UX gap）
- pgl.yml 中 `compliance.data_retention` 字段 → 支柱三（隐私）
- Charter 第三条「公允版税回流」+ Royalty Router → 附加价值（公允回流）

**所以 Charter 不是法律约束，是「让这三大支柱真的能兑现」的底层契约。**
