## 0. 一句话定位（最终版）

> **Hyphae 帮特定场景的小组织，在保护隐私的前提下，训练出适合他们自己的 AI。**
> **我们卖的不是人力服务，是"把零散业务 AI 化 + 持续进化"的产品化能力；最难也最值钱的是"找到正确的训练路径"——这需要业务上下文，正是大厂的盲区。**

---

## 1. 核心修正：不靠贴身服务赚钱

### 1.1 为什么贴身服务是死路

- 小机构养不起优秀工程师；我们更养不起给每家配工程师
- 人力一对一服务 = 成本随客户数线性爆炸 = 不 scale
- 这是传统 SI / 咨询公司的陷阱，**Hyphae 绝不进**

### 1.2 我们真正交付的（产品化、可复利）

| # | 价值 | 形态 | 是否人力密集 |
|:---:|:---|:---|:---:|
| ① | **碎片流程 AI 化** | 把零散的活儿一件件自动化（文案/海报/对账/提醒）| 否（产品）|
| ② | **系统数据同步** | 接入已有系统（钉钉/CRM/Excel），数据自动流动 | 否（产品）|
| ③ | **持续进化** | 每月自动增量训练，越用越懂 | 否（自动闭环）|
| ④ | **行业判断推送** | 主动推决策建议，不用客户开口 | 否（产品）|

### 1.3 收入结构

```
开源底座（免费）          建信任 + 攒数据 + 降低决策门槛
      ↓
订阅式产品价值（主力）     ①②③④ 持续价值，月费/年费
      ↓
行业模型训练（高价值）     帮某行业训出可用 AI，一次性 + 持续迭代
```

**关键**：收入与"客户数 × 产品价值"挂钩，**不与"工程师人头"挂钩**。这才 scale。

## 2. 真护城河：找到正确的训练路径

### 2.1 最难的不是训练，是找路径

> 训练本身（LoRA/QLoRA）是成熟技术，谁都能跑。
> **真正难的是：哪个微调目标、喂什么数据、配什么决策框架、解决哪个真实业务痛点。**
> 这就是"找到正确的路径"——80% 的工作量在这里（见 [hyphae-training/TRAINING_PHILOSOPHY](../hyphae-training/TRAINING_PHILOSOPHY_AND_RULES.md)）。

### 2.2 为什么这是大厂的盲区

| 大厂有 | 大厂没有 |
|:---|:---|
| 顶级工程师 | 小服装厂/民宿/诊所的业务上下文 |
| 海量算力 | 对单个小组织的持续跟进 |
| 通用大模型 | "这家店该不该摆集市"的判断范式 |

> 即便大厂有最强的工程师，**没有业务上下文 + 没有持续跟进，做不出这种微调**。
> 创始人 20 年软件 + 10 年 ERP，就是这块业务上下文的来源。

### 2.3 护城河必须产品化（否则变成本黑洞）⚠️

**风险**：如果每家的"路径"都靠人现找、靠人持续盯 → 又回到贴身服务的成本陷阱。

**破解**：把"找路径"沉淀为**可复用、可复利的资产**：

```
行业 playbook / SOP        每个行业的"找路径"只做一次，
                          摊销给该行业所有组织
      +
联邦学习跨同行聚合          同行业多组织共训行业模型，
                          数据不出门，经验自动汇集（见 §4）
      +
自动进化闭环              "持续跟进"做成产品（月度增量训练），
                          不是人盯
```

→ 业务上下文的人力活儿，**每个行业做一次**，之后是数据资产在复利，不是人力在重复。

## 3. 落地与增长：运营合伙人 + 口碑闭环

### 3.1 区域/行业运营合伙人（分润制）⭐ 破解人力陷阱的关键

> 创始人 2026-06-24 补充：引入外部区域和行业运营人员，分润 + 完成落地部分 + 行业经验补充。

**模型**：

```
Hyphae 总部（平台方）
  ├─ 提供：开源平台 + 训练技术 + 隐私基础设施 + 行业 playbook
  └─ 不做：雇佣工程师挨家落地

区域/行业运营合伙人（渠道方）
  ├─ 带来：本地资源 + 行业经验 + 客户关系 + 落地执行
  ├─ 负责：完成落地部分 + 补充行业经验（反哺 playbook）
  └─ 获得：分润（与平台按比例分成）
```

**为什么这解决了人力陷阱**：
- 落地的人力**不是 Hyphae 雇的**，是合伙人自带的
- 分润**对齐利益**：合伙人卖得越多赚得越多，自驱动
- 合伙人的**行业经验反哺**行业 playbook，让护城河越挖越深
- Hyphae 总部保持**轻**（平台 + 技术 + 数据资产），可规模化

**类比**：Red Hat 的区域合作伙伴 / Shopify 的 Partner 生态 / 保险代理人模型——平台轻，渠道重，分润绑定。

### 3.2 以成交为闭环，口碑传播 ⭐

> 创始人补充：以成交为闭环，解决实际问题为目标，口碑传播。

**原则**：
- **不烧钱投广告**，靠"真解决了问题"驱动转介绍
- **成交 = 闭环验证**：客户真付费 + 真用起来 + 真见效，才算一个完整闭环
- **口碑传播**：一个小服装厂老板用得好，会告诉同行三个老板（中小组织圈子小、信任链短、口碑传播极快）
- 区域/行业运营合伙人本身就是口碑节点

**增长飞轮**：
```
解决一个真实痛点 → 客户见效 → 口碑转介绍 → 合伙人复制到同行
      ↑                                              ↓
   playbook 越来越准  ←  行业经验反哺  ←  更多同行组织数据
```

## 4. 联邦学习：跨同行聚合的技术底座

> 详见 [hyphae-training/FEDERATED_LEARNING.md](../hyphae-training/FEDERATED_LEARNING.md)（专项调研）。

**为什么联邦学习是 Hyphae 的关键拼图**：
- 同行业多个小组织，单家数据不够训出好模型
- 但他们**不愿、也不能共享原始数据**（隐私 + 竞争）
- 联邦学习让他们**贡献模型更新而非数据**，共训一个"行业 LoRA"
- 技术上：只交换 LoRA delta（8-40MB/轮，非 14GB 全模型），2026 年已实用

**与 Hyphae 两层 LoRA 架构的完美契合**：
- 学术界的 **FedALT**（个性化 LoRA + Rest-of-World 共享 LoRA）= Hyphae 的"客户 LoRA + 行业 LoRA"
- 每家保留自己的个性化层（数据不出门），共享行业知识层

## 6. 我（产品负责人）对这套定位的评估

### 6.1 认同（这是最锋利的一版）

1. 贴身服务死路 → 产品化 + 合伙人分润，正确且 scale
2. "找路径需要业务上下文 + 持续跟进，是大厂盲区" = 真护城河
3. 运营合伙人分润 = 破解人力陷阱的关键（落地人力不是 Hyphae 雇的）
4. 口碑闭环 = 中小组织圈子的最优获客（信任链短、传播快）

### 6.2 仍需钉死的三个风险

| 风险 | 应对 |
|:---|:---|
| "找路径"若不产品化 → 成本黑洞 | 强制沉淀行业 playbook + 联邦聚合，每行业做一次 |
| 合伙人质量参差 → 砸口碑 | 合伙人认证 + playbook 标准化 + 总部质量兜底 |
| SMB 定制 AI 诉求仍早期 | 从"已有诉求 + 痛点明确"的行业先切（服装厂/民宿/诊所/培训）|
| 隐私保护是前提，技术必须扎实 | 本地训练默认 + 联邦 + TEE 三层（见 training 研究）|

### 6.3 一句话

> **这套定位把 Hyphae 从"重人力的 AI 咨询"彻底改造成"轻平台 + 合伙人分润 + 数据复利"的可规模化生意。**
> **唯一的生死线：把"找路径"产品化（行业 playbook + 联邦聚合），否则护城河会反噬成成本黑洞。**
