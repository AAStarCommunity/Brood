# OUR_MOAT.md — Hyphae 的护城河

> **核心原则**：不在 Firework 强的维度（GPU 算子、PyTorch 团队、千亿参数推理优化）正面打仗。**换战场**，在 Firework 弱或拒绝服务的维度建立护城河。

---

## 1. 五大护城河（按 sustainability 排序）

### 护城河 1：**业务流程 / 行业 know-how**（最关键，源自创始人 10 年 ERP 经验）⭐⭐⭐⭐⭐

**为什么这是真护城河**：

Firework 团队是世界顶级 PyTorch 工程师，但他们**完全不懂**：
- 一个 30 人贸易公司的报关单流程
- 一个 50 人律所的卷宗管理
- 一个 100 人制造业的 BOM 与车间工单
- 一个社区医院的患者就诊路径
- 一个城市学校的教务系统

**这些"复杂的业务事务"才是中小组织 AI 化的真正难点**：
- 模型部署只占 20% 工作
- **80% 工作是把业务流程拆解为 AI 可执行的步骤**
- 这需要**领域经验**，不是 GPU 工程师能补的

**创始人 10 年 ERP 经验意味着**：
- 熟悉企业内部流程的真实样貌（不是文档上的样貌）
- 知道哪些事 AI 能做、哪些不能、哪些做了反而麻烦
- 能直接画出"把客户的混乱业务搬上 AI"的迁移路径图
- 这是 Firework 团队**5-10 年也补不上**的领域护城河

**对应客户场景**：
> Firework 客户问："给我个 Llama 4 API。"
> Hyphae 客户问："我们公司每天 200 张报关单录入，哪些能 AI 做？"
> 前者是工具，后者是咨询 + 工具。**我们卖咨询 + 工具的组合，Firework 卖工具**。

### 护城河 2：**中小组织聚焦 + Firework 拒绝的市场**（市场护城河）⭐⭐⭐⭐⭐

Firework 明确不服务的客户类型，我们独占：

| 客户类型 | 全球数量级 | Firework 服务 | Hyphae 服务 |
|:---|:---:|:---:|:---:|
| 10-200 人小公司 | 千万级 | ❌ | ✅ |
| 合规敏感行业（医疗 / 律所 / 政府 / 教育） | 百万级 | ❌ | ✅ |
| 传统行业转型（ERP / CRM / 制造） | 百万级 | ❌ | ✅ |
| 本地化部署需求（中国 / 一带一路） | 百万级 | ❌ | ✅ |

**TAM 估算**：
- 全球中小组织 ~5000 万
- 渗透率 0.1% = 5 万客户 × 客户 LTV $5k-$50k = **$2.5 - 25 亿 ARR 潜力**
- Firework 完全不在这块投入资源

**这是 blue ocean 护城河**：等 Firework 想下沉时，我们已经吃下品牌 + 渠道 + 案例 + 行业 know-how。

### 护城河 3：**Mycelium 生态协同**（生态护城河）⭐⭐⭐⭐

Hyphae 不是孤立产品，是 Mycelium 生态的一环：

| 协同对象 | 协同方式 |
|:---|:---|
| **AAStar AirAccount** | 组织成员用 passkey 登录，无须邮箱密码 |
| **SuperPaymaster** | 溢出 API 调用走 aPNTs 支付（与 FangPay 共用计费栈）|
| **iDoris** | 组织内每个员工的个人 AI 助手 |
| **Agent24** | 桌面端 Agent 框架，企业版直接嵌 |
| **FangPay** | 中小商家收款 + Hyphae 智能助理双工具 GTM |
| **MushroomDAO Cos72** | 组织成员的会员卡 / 积分系统 |
| **HyperCapital** | 商业服务（onboarding + 月度运维）|

**生态护城河效应**：
- Firework 必须从零搭账户 / 计费 / 商业服务体系
- Hyphae 直接接入 Mycelium 已有基础设施（节省 60-80% 工程投入）
- 客户接入 Hyphae = 一站获取 8 个产品的协同价值
- Firework 客户用 Firework 只能得 Firework

### 护城河 4：**开源 + 数据主权品牌**（信任护城河）⭐⭐⭐⭐

中国 + 全球合规敏感行业的核心痛点：**数据不能上云**。

Firework 必须把数据传到 Firework 云端推理。Hyphae：
- ✅ **平台代码全开源**（Apache 2.0），客户可审计每行代码
- ✅ **数据 100% 在客户硬件**（自己机房 / NAS / GPU 工作站）
- ✅ **想退出随时把代码 + 数据 + 模型权重打包带走**
- ✅ **没有 vendor lock-in**

**对应客户场景**：
> 律所："我们的卷宗能传到 Firework 美国服务器吗？" → "不能。" → 律所放弃 Firework。
> 律所："Hyphae 怎么部署？" → "您机房一台带 GPU 的服务器，30 分钟装好。" → 律所成单。

**品牌定位差异**：
- Firework = "最快的开源模型 cloud"
- Hyphae = **"你的数据不离开你的硬件，但你也能用上 AI"**

### 护城河 5：**HyperCapital 辅导式商业服务模型**（运营护城河）⭐⭐⭐

继承 FangPay / Loyalty Network 同一套商业服务模型：

| 服务包 | 内容 | 价格 |
|:---|:---|:---:|
| **A. Onboarding** | 一对一辅导硬件采购 + OS 安装 + Hyphae 部署 + 业务 Agent 调试 | $499-$2999 一次 |
| **B. 月度运维** | 模型更新 + 微调迭代 + 故障响应 + Agent 优化 | $99-$999 / 月 |
| **C. 企业定制** | 深度业务流程改造 + 多 Agent 编排 + SLA | $5k+ 项目 |

**关键纪律**（与 FangPay 同）：
- HyperCapital **不持有客户数据 / 模型权重 / 服务器密钥**
- 用客户自己的资源做操作（账号在客户手里）
- 客户随时可解约 + 自接管 + 走人

**对中小组织的吸引力**：
- "我不懂 AI" → 包 A 教你
- "我没人维护" → 包 B 帮你管
- "我们公司有特殊业务" → 包 C 定制

**对 Firework 的差异**：
- Firework = 自助 cloud（不懂的客户被排除）
- Hyphae = 半自助 + 辅导服务（不懂的客户也能用）

## 3. 护城河的演化路径（3 年）

### Year 1：奠基
- 占住 10-20 个种子中小组织（不同行业各 2-3 个）
- 沉淀业务流程模板库（医疗 / 律所 / 制造 / 教育 / 贸易各 1 套）
- HyperCapital 服务包 A/B 标准化

### Year 2：复制
- 扩展到 500-1000 客户
- 行业模板库扩到 10+ 行业
- 与 Mycelium 其他产品深度协同
- 中国市场 + 东南亚 + 中东渐次进入

### Year 3：网络效应
- 5000+ 客户
- 行业模板成为事实标准
- HyperCapital 商业服务规模化（培养渠道伙伴）
- **护城河深到 Firework 想下沉也已晚**
