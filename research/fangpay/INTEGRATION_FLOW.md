# INTEGRATION_FLOW.md — 最简集成流程

> **核心要求**：商家"配置即可 run"。
> 商家流程 = **填邮箱 + 填钱包地址 + 生成页面**（3 步，5 分钟）
> 用户流程 = **打开链接 → 签名 → 完成**（2 步，30 秒）
> 集成方式 = **一行 `<script>` 嵌入** 或 **直接发支付链接**（零后端）

### 1.3 极简账户模型（无传统注册）

```typescript
interface MerchantSlug {
  slug: string;                  // "zhangsan-ebook" - URL 友好
  merchantAddress: string;       // 0x... (收款地址)
  emailHash: string;             // sha256(email + salt)  ← 只存哈希
  adminKey: string;              // 随机 32 字节 - 商家访问后台用
  product: {
    name: string;
    priceUSD: string;
    currency: 'USDC' | 'USDT';
    chains: number[];            // [8453, 42161]
    deliverType: 'download' | 'record' | 'contact';
    deliverContact?: string;     // email / telegram / discord
    deliverFile?: string;        // IPFS hash (for download)
  };
  gasQuota: {
    freeRemaining: number;       // 10 → 0
    apntsBalance: bigint;
  };
  createdAt: number;
}
```

**为什么不要传统注册**：
- 商家不需要密码，**adminKey URL** 就是身份（类似 Excalidraw、tldraw、PrivateBin 模式）
- 邮箱只存哈希，平台无法重置（用户自己保管 adminKey）
- 任何想"找回"的请求需要邮箱原文 + 数字签名（防止社工）
- 这是真的"无账户"（accountless），符合数字主权

## 3. 商家集成 — 三种方式

### 3.1 方式 A：直接发支付链接（零代码）

商家不需要任何技术能力。直接把链接发给买家：
```
https://pay.fangpay.io/zhangsan-ebook
```
适合：Twitter/Telegram/邮件营销、独立创作者打赏

### 3.2 方式 B：一行嵌入（适合任何静态网站）

```html
<!-- 放在你的商品页任何位置 -->
<script src="https://cdn.fangpay.io/v1.js"></script>
<fang-pay slug="zhangsan-ebook"></fang-pay>
```

渲染效果：一个浮在页面上的支付按钮 + 弹窗（完全独立 iframe，不污染主站 CSS）。

适合：Webflow / Framer / Notion Sites / WordPress / 任意 HTML 网站

### 3.3 方式 C：React 组件（适合开发者）

```bash
npm install @fangpay/react
```

```tsx
import { FangPayButton } from '@fangpay/react';

export default function ProductPage() {
  return (
    <FangPayButton
      slug="zhangsan-ebook"
      onSuccess={(tx) => alert('支付成功! ' + tx.hash)}
    />
  );
}
```

> 注意：方式 C 的 npm 包**不需要 API key**。所有商家配置都在 slug 里，前端零密钥。

## 4. 零后端架构

### 4.1 关键点

```
                          ┌──────────────────┐
                          │ pay.fangpay.io   │
                          │  (静态 SPA)       │  ← Cloudflare Pages
                          └────────┬─────────┘
                                   │
                  ┌────────────────┼────────────────┐
                  ▼                ▼                ▼
        ┌─────────────────┐  ┌──────────────┐  ┌──────────────┐
        │ relay.fangpay.io│  │ KV (slugs)   │  │ Chain RPC    │
        │ (Cloudflare     │  │ (Cloudflare  │  │ (Alchemy /   │
        │  Worker)        │  │  KV)         │  │  Infura)     │
        │                 │  │              │  │              │
        │ POST /relay     │  │ GET slug →   │  │ eth_send-    │
        │ POST /quote     │  │ merchant cfg │  │ RawTransaction│
        └─────────────────┘  └──────────────┘  └──────────────┘
```

**商家不需要：**
- ❌ 自己的服务器
- ❌ 数据库
- ❌ API key 管理
- ❌ Webhook 接收器（可选，需要才配）

**FangPay 平台需要：**
- ✅ Cloudflare Pages（静态站托管，免费）
- ✅ Cloudflare Worker（Relay 调度，按调用计费）
- ✅ Cloudflare KV（商家配置存储）
- ✅ 1-2 个 EOA 钱包持有 ETH（Relay gas 池）
- ✅ aPNTs/USDC 兑换池（用于 aPNTs 购买）

整套月运营成本估算（5000 商家、10 万笔/月）：
- Cloudflare：$50-200/月
- Relay gas：$2000-5000/月（=10 万笔 × $0.02 L2 gas + buffer）
- ETH 储备：$10k 一次性
- **总：约 $5k/月 ≈ $0.05/tx**，加 30% 毛利 → 收 $0.065/tx 即可，**远低于 1 aPNTs (~$0.01)** ← 这里 aPNTs 价格需要重新校准

> ⚠️ 上述价格是 L2 假设。如果走 Ethereum mainnet 单笔 gas 就要 $2-5，定价模型必须强制商家选 L2，或主网走"商家加价转嫁给买家"。

## 5. 与 jhfnetboy/FangPay 已有 SDK 设计的关系

`jhfnetboy/FangPay` 的 PRODUCT_DESIGN.md 设计了一个 `@fangpay/sdk` 包，含 React/Vue/Web Component。

本研究目录的"极简集成"建议是 **PRODUCT_DESIGN.md 的子集**，砍掉：
- ❌ AI Skill 配置对话（v1 不需要，UI 表单更简单）
- ❌ NFT 凭证（v1 不需要，链上 hash 就是凭证）
- ❌ 退款 / 订阅 / 积分（v1 不做）
- ❌ Dashboard 多页面（v1 单页 + adminKey URL）

保留：
- ✅ Protocol Router（自动选 Path A/B）
- ✅ Web Component 嵌入方式
- ✅ Relay 中继 + Gas Credit 计费
- ✅ Apache 2.0 全开源

## 6. 上线后第一周需要验证的指标

| 指标 | 目标值 | 测量方法 |
|:---|:---|:---|
| 商家从打开站到生成页时间 | < 3 min | 前端埋点（无 PII） |
| 买家从打开链接到支付成功时间 | < 60 sec | 前端埋点 |
| Path A 成功率 | > 95% | Relay 服务日志 |
| Path B 完成率（含 CEX 提币） | > 60% | (买家点 Path B 数 / 完成数) |
| 商家用完 10 笔免费配额比例 | > 30% | KV 统计 |
| aPNTs 购买转化率（用完 10 笔后） | > 50% | 购买页转化 |

如果 6 周内这 6 个指标都达标，说明模式跑通，可以推 v2（加 NFT 凭证 / Dashboard / 多商品支持）。

否则砍掉某些路径或重新定位。
