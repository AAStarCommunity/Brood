## 0. 一句话总览（v0.2 — 2026-06-22 修订）

> **最终设计**：**链上做账（海外）+ 传统做面（中国）+ 单向同步桥**。
>
> - 海外端：链上账本 + 跨家联盟（模式 B），加密原生体验
> - 中国端：传统数据库 + 普通积分商城（模式 A），web2 体验，**无须 license**
> - 商家：可选境内 / 海外 / 双轨入驻
> - 中国用户全程感知"普通积分商城"，不接触钱包 / 链 / 币
> - PIPL 合规：境内用户个人信息**不出境**，只传匿名 ID + 积分余额
>
> 详见 [CHINA_REALITY_CHECK.md](./CHINA_REALITY_CHECK.md)（最新且最重要）。

## 3. 关键结论 5 条

### 3.1 合规模式只有一种

跨商家积分要合规，**必须照搬航空联盟模式**（每家发自己的、双边汇率、法币 B2B 结算、限定用途、有时效）。
**没有"创新的法律空间"**，但**有"复制 + 链上升级"的技术空间**。

### 3.2 链上账本是合规盟友，不是敌人

链上 = 透明 + 不可篡改 + 可强制时效 + 可强制限定用途 → **比传统 SaaS 更容易合规**。
前提：按 [LEGAL_COMPLIANCE §10](./LEGAL_COMPLIANCE.md#10-给本研究的硬约束设计阶段必须遵守) 10 条硬约束设计。

### 3.3 中国大陆 — 看具体模式 + 双层数据架构（2026-06-22 二次修订）

⚠️ **原判断过严，已二次修订**。用户先反馈德勤同学说法，再补充"双层数据架构"洞察后：

**最终推荐：单一组合方案** —— 中国 + 海外 + 链上 同时跑通

```
底层（海外）：链上账本 + 跨家联盟（模式 B） —— 海外用户原生体验
     │
     │ 单向同步（事件驱动 + 匿名化 ID + 规避 PIPL）
     ▼
境内（中国）：传统数据库镜像 + 普通积分商城（模式 A） —— 中国 web2 体验
```

- ✅ 中国端：商家 + 用户都不知道有区块链，完全 web2 商城 → **无须 license**
- ✅ 海外端：完整链上 + 钱包 + 跨家联盟 → 加密原生差异化
- ✅ 桥接：链上数据 → 中国 DB 单向同步，**仅传匿名 ID + 余额**（PIPL 合规）
- ✅ 商家：可选境内入驻 / 海外入驻 / 双轨入驻
- ✅ 退出灵活：任一端可独立关停，不影响另一端

详见 [CHINA_REALITY_CHECK.md §8 双层数据架构](./CHINA_REALITY_CHECK.md#8-双层数据架构--解锁全球一套底层中国合规外壳2026-06-22-用户补充)。

### 3.4 清算服务方角色 = HyperCapital 最大商业机会

类比 Star Alliance Services GmbH：
- 不是支付机构（不接触资金）
- 不是积分发行人（不发币）
- 而是**技术服务 + 撮合账本 + 商业咨询**
- 收：年费 + 按笔技术费 + 月度运维包 + 一次性 onboarding
- 与 Mycelium 双生模型完美匹配

### 3.5 现在不要做方案 B

**先做方案 A（task-2 Cos72 Lite + AAStar OpenPNTs）跑通 3-5 个真实商家 6 个月**。
**6 个月后如商家自发要求"跨家互通"** → 启动方案 B 试点。
**如果没人问 → 联盟是设计师幻想，省下钱不要做**。
