# CASE_STUDIES.md — 商业积分联盟案例研究

> **目的**：在写法律分析和设计方案之前，先理解**别人怎么做**。
> **覆盖**：航空联盟（用户提到的星空联盟）、酒店联盟、信用卡积分、中国本土案例、加密圈尝试、失败案例。

## 1. 星空联盟 / Star Alliance（1997-至今） ⭐ 用户引用的标杆案例

### 1.1 基本事实

- 成立：1997 年（5 家航空公司创立）
- 当前成员：26 家航空公司（含国航、汉莎、新航、加航、ANA 等）
- 法律实体：**Star Alliance Services GmbH**，注册德国法兰克福
- 业务规模：年覆盖 6 亿+ 旅客
- 类似联盟：Oneworld（13 家）、SkyTeam（19 家）

### 1.2 积分（里程）流通机制

**关键事实**：**里程不能"互换"，只能"互相承认在自家计划里的累积/兑换"。**

```
正确理解：
  ✓ 国航金卡里程可以在汉莎航班上累积（汉莎报数据给国航，加到用户的国航账户）
  ✓ 国航里程可以兑换汉莎的机票（国航向汉莎"购买"机票，用国航里程作为账目记录）
  ✗ 国航 1000 里程"变成"汉莎 700 里程 —— 这种"代币互换"实际上是不存在的
```

里程**始终归属用户加入的那家航司**（FFP, Frequent Flyer Program），而非"联盟里程池"。

### 1.3 清算机制

每月 / 每季度，Star Alliance Services 充当**结算账本**：

```
案例：用户用国航 50,000 里程兑换了汉莎北京-法兰克福机票
  
  在账本上：
    1. 国航：从用户账户扣 50,000 里程
    2. 汉莎：向用户出机票
    3. 联盟账本：国航 "欠" 汉莎一笔票款
  
  双边轧差结算（用真金白银）：
    国航本月共欠汉莎  $X
    汉莎本月共欠国航  $Y
    净额 |X - Y| 由欠方实际打款给收方
  
  Star Alliance Services 仅做账本撮合，不持有钱
```

### 1.4 法律结构

| 层级 | 内容 |
|:---|:---|
| **顶层** | 26 家航空公司多边协议（Multilateral Agreement） |
| **第二层** | 每两家之间另签 Bilateral Loyalty Agreement（定汇率、定兑换规则） |
| **第三层** | Star Alliance Services GmbH 作为**技术服务商 + 账本管理者**，不拥有里程，不做支付机构 |
| **运营** | 每家航司**自己的里程计划**遵守本国监管（中国国航受民航局管，汉莎受德国 BaFin） |
| **税务** | 每家航司自己处理"里程兑换"的会计/税务（一般做成"商品折扣"） |

### 1.5 为什么这个模式合规

1. **不是统一货币**：每家里程只是该航司的负债，不是联盟发行的"代币"
2. **不可兑换现金**：里程绝大多数 jurisdictions 都不可换现金
3. **限定用途**：兑换机票 / 升舱 / 酒店 / 商品（**封闭使用场景**）
4. **有时效**：里程一般 2-3 年清零
5. **联盟运营方仅做技术服务**：不持有里程余额，不是支付机构
6. **航司之间用法币结算**：积分流通 → 但**钱的流动是合规的法币 B2B 结算**

### 1.6 时效设计的真实原因

> 用户问到"时效是合规还是商业"

答：**双重原因**：
- **商业**：减少"长期负债"压力（里程账上算公司负债，时效让负债自动减计）
- **合规**：长期不过期的积分会被会计/税务认定为"准货币" → 更接近预付卡 → 更严监管

## 2. 万豪 Bonvoy / 凯悦 World of Hyatt / 雅高 ALL（酒店联盟）

### 2.1 与航空联盟的区别

- 万豪 Bonvoy 是**单一品牌母公司下**的多酒店品牌（万豪、丽思卡尔顿、喜来登、艾美等）—— 不是真正的"联盟"，是**同一家公司**
- 凯悦 World of Hyatt 同上
- 真正的跨公司联盟在酒店业较少见

### 2.2 跨业互通

许多酒店集团与航空公司互通：
- 万豪 Bonvoy ↔ 美联航 MileagePlus（按 3:1 换）
- 凯悦 ↔ 美航 AAdvantage

机制同 §1.3 —— **双边协议 + bilateral exchange rate + B2B 法币结算**。

### 2.3 关键启示

**没有所谓"通用酒店里程币"**，全是双边协议下的"在账本里改数字"。

## 3. 信用卡积分（Amex MR / Chase UR / Citi TY）

### 3.1 模式

- 信用卡发行方（如 Amex）发自己的积分（Membership Rewards）
- 与多家航空 / 酒店签 bilateral transfer partner 协议
- 用户可把 MR 转入合作伙伴账户（不可逆，1:1 或 1:0.7 等比率）
- Amex 与合作伙伴**法币 B2B 结算**

### 3.2 关键差异

- 信用卡积分**直接绑定信用消费返还**（消费 1 美元 → 1 积分）
- 这使得积分"看起来像折扣返还"，法律定性更清晰
- 但因为积分**可累积、可转让到合作伙伴**，部分国家（如澳大利亚）已开始监管

### 3.3 法律风险点

2017 年澳大利亚 ASIC 调查信用卡积分计划，最终结论：
- 积分本身仍是"折扣返还"
- 但其"市场价值"必须明确披露
- 不构成证券，但有信息披露义务

## 4. 中国本土案例

### 4.1 合规的案例

| 案例 | 模式 | 合规要点 |
|:---|:---|:---|
| **招行积分 / 中信积分** | 单家银行发，可换商城商品 / 抵积分 | 单一发行人 + 不可换现金 + 商城封闭场景 |
| **京东豆 / 淘宝积分** | 平台发，可抵该平台消费 | 单一平台 + 封闭场景 |
| **微信支付分** | 不是积分，是信用评分 | 不参与本研究 |
| **国航凤凰知音** | 国航发，星空联盟内可兑换 | 同 §1，多边协议 |
| **携程 / 美团积分** | 各自发，互不兑换 | 单一平台 |

### 4.2 不合规 / 被叫停的案例

| 案例 | 问题 | 监管动作 |
|:---|:---|:---|
| **早期"积分宝" 等 P2P 积分交易平台** | 用户间转让积分形成二级市场 | 2017-2018 年陆续被叫停 |
| **多家美容/健身预付卡跨店通用** | 实质形成"多用途预付卡" | 央行《支付机构预付卡业务管理办法》明令禁止无牌经营 |
| **某早期"区块链积分"项目** | 发了可在 DEX 交易的代币 | 2017 年 9 月"9·4 公告" 直接归类为 ICO，全部停止 |
| **某网约车公司"积分换股票"促销** | 期待收益 + 共同事业 → 证券 | 证监会约谈，叫停 |

### 4.3 中国监管的核心红线

来自央行《非金融机构支付服务管理办法》和《支付机构预付卡业务管理办法》：

> "未经中国人民银行批准，任何非金融机构和个人不得从事或者变相从事支付业务。"

**变相支付业务的认定**：
- ❌ 多商家通用 + 可累积 + 可兑换商品 → 类预付卡
- ❌ 跨商家可流转 + 不限制用途 → 类电子货币
- ❌ 可在二级市场转让 → 类证券
- ❌ 可兑换法币 → 类支付工具

**安全做法**：
- ✅ 单一商家发 + 仅本商家使用 + 不可流转
- ✅ "折扣券" / "优惠券" 形式（绑定单次购买）
- ✅ 明确**不是货币**、**不可兑换现金**、**仅限本店**

### 4.4 中国大陆"跨商家积分流通"的现实

**严格说**：在中国大陆做"中小商家跨家积分流通 + 用户积累 + 兑换"，几乎一定会触发"变相多用途预付卡"红线。

**例外路径**：
1. 申请**支付牌照 + 多用途预付卡牌照** —— 门槛极高（需缴存 100% 备付金，资本金 1 亿+，央行严格审批）
2. 借道**银行 / 持牌支付机构**作为发行人 —— 商家上挂在银行积分系统下
3. 走**会员费 / 服务订阅**模式 —— 不用积分概念

## 5. 加密圈相关尝试

### 5.1 Loyyal（2014-至今）

- 区块链积分互换平台
- 模式：每家发自己 ERC-20 积分，链上跨家兑换
- 状态：仍在运营但小众
- 启示：**技术可行，但市场接受度极低**（用户更习惯 web2 体验）

### 5.2 Reddit Community Points（2020-2024，已下线）

- Reddit 给社区发 ERC-20 积分（如 MOON / BRICK）
- 用户挖矿 + 用于 community boost
- 2024 年 Reddit 全部下线（运营成本 + 监管）
- 启示：**协议方下线 → 用户积分全部归零** → 验证了"中心化平台 + 链上积分" 模式不可持续

### 5.3 StepN 等 Move-to-earn

- 用户运动赚 GST/GMT
- 二级市场流动 → 投资属性
- 多国证券监管警告
- 启示：**积分**一旦有"投资期待收益"就变证券

### 5.4 Bonfire / Galxe Quests / Layer3

- 任务平台发"积分"（air points / experience points）
- 不可二级市场交易 + 兑换具体权益（NFT / 空投 / 实物）
- 状态：合规运营中
- 启示：**任务积分 + 兑换具体权益 + 不上 DEX** = 当前最稳妥模式

### 5.5 Blackbird（餐饮 Web3 积分）

- 2023 年起，为餐厅 / 咖啡馆发链上积分
- 单店发 + 跨店可兑换（仅限其网络内）
- 用 FLY 代币作为底层（用户隐藏代币细节）
- 状态：纽约市运营，扩展中
- 启示：**最接近用户问题的设计** — 单店发 + 联盟内兑换 + 用户无感

### 5.6 Tomb Finance / 各种 DAO 积分

- 仅做内部治理 / 投票，不流通
- 不在本研究范围

## 7. 跨案例总结：**合规跨商家积分的 7 个共性特征**

把所有合规案例（航空 / 酒店 / 信用卡 / Blackbird / Bonfire）放一起看，共性如下：

| # | 特征 | 反例 |
|:---:|:---|:---|
| 1 | 每家**自己发行**积分（不是联盟统一发） | 统一代币 |
| 2 | 联盟运营方**不持有**用户积分余额 | 联盟做托管 |
| 3 | 用户视角"我有 N 积分来自 X 家" → 联盟做**双边账本撮合** | 单一"联盟币" |
| 4 | 兑换**结果限定用途**（机票/酒店/商品） | 可换现金 |
| 5 | **不构造二级市场**（不能在 DEX / 第三方交易） | 可上交易所 |
| 6 | 有**时效**（积分自动过期） | 永不过期 |
| 7 | 联盟内**法币 B2B 结算**（航司之间用真金白银轧差） | 用代币结算 |

> ⭐ 这 7 条**就是合规设计的硬约束**。本研究的设计方案必须满足全部 7 条，否则就在踩红线。

## 8. 给本研究的启示

| 启示 | 影响 |
|:---|:---|
| **抛弃"通用联盟币"幻想** | 不要做"OpenPNTs as universal loyalty currency" |
| **复制航空联盟结构** | 商家各发各的，联盟做撮合账本 |
| **法币 B2B 结算是正路** | 不要在链上代币结算，用 USDC 做 B2B 月度轧差 |
| **限定用途 + 时效 + 不可现金兑换** | 避免预付卡定性 |
| **联盟运营方 = 技术服务商** | 不是支付机构、不是发行人 |
| **中国大陆需特别警惕** | 一旦"跨多家流通 + 可累积兑换商品"，红线即触发 |
| **Blackbird 是最佳参考** | Web3 餐饮联盟，建议深入研究他们的法律结构 |

---

## 9. 一句话

> **跨商家积分的"合规已解"模式 = 航空联盟模式 + 链上账本透明化**。
> **没有"创新"的法律空间**，但**有"复制 + 升级"的技术空间**。
> **核心创新点**：链上账本让"清算服务方"的运作 100% transparent + auditable，监管反而更友好。
