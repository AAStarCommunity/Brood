## 1. 用户原话（精简整理）

> "在全球范围内和中国国内，我们帮助中小商家发行积分，他们之间的积分流动如何才能做这种商业积分的互换合法合规？
>
> 我知道有星空联盟之类的航空公司，他们的商业积分可以互换，但互换是受限制的：
> - 只在组织内
> - 互换的结果是抵扣机票（抵扣购买机票的金额）
> - 这些互换的积分是有时效的，也有一些限制
> - 互换积分背后有一家共同使用的积分服务公司来完成账目的记录和结算
>
> 换句话说，用户有 1000 积分，他的 1000 积分可能来自三个航空公司。那他现在要用这 1000 积分去兑换比如说第四个航空公司的机票。那实际上这四个航空公司必须在一个航空联盟中，并且在这个航空联盟的账目中，要记录航空公司收入了多少积分、支出了多少积分。
>
> 但这背后的账目怎么做、怎么合法、怎么合规，我其实不是太了解。"

## 2. 问题结构化（5W1H）

### 2.1 Who（角色）

| 角色 | 描述 | Brood 生态对应 |
|:---|:---|:---|
| **发行商家 (Issuer)** | 中小商家（独立站、咖啡店、餐饮、本地服务） | Cos72 用户、FangPay 商家 |
| **终端用户 (Holder)** | 持有跨多家积分的消费者 | AirAccount 用户 |
| **核销商家 (Redeemer)** | 接受跨商家积分兑换的商家 | 同 Issuer，但可能不同 |
| **联盟运营方 (Alliance Operator)** | 制定规则、协调清算 | MushroomDAO + HyperCapital |
| **清算服务方 (Settlement Provider)** | 记账 + 双边轧差 + 资金结算 | ⭐ 这是用户最不清楚的角色 |
| **监管机构 (Regulator)** | 各国央行/SEC/MAS/PBoC | 不可控外部约束 |

### 2.2 What（积分本身是什么）

待回答：
- Q1：积分 = 折扣权？预付凭证？货币替代？证券？
- Q2：跨商家流通时，积分的**性质是否改变**？
- Q3：积分能否兑换法币 / 等价数字资产 / 其他积分？

### 2.3 Where（地理范围 + 司法辖区）

| 地区 | 核心法律框架 | 严格度 |
|:---|:---|:---:|
| **美国** | Howey Test + 各州预付卡法 + FinCEN MSB | 中 |
| **欧盟** | MiCA（2024 生效）+ E-money Directive | 中-高 |
| **新加坡** | PSA（2019） | 中 |
| **香港** | SVF (Stored Value Facility) Ordinance | 中 |
| **中国大陆** | 《非金融机构支付服务管理办法》+《支付机构预付卡业务管理办法》 | ⭐ 极严 |
| **日本** | 资金决济法 / 前払式支付手段 | 中-高 |
| **印度** | RBI Wallet 规定 | 高 |

用户重点关心：**全球范围 + 中国国内**

### 2.4 When（时效约束）

用户已经观察到的约束：
- 积分**有时效**（如里程 2-3 年清零）
- 兑换有**窗口**（黑名单日期、淡旺季）

待回答：
- Q4：时效本身是合规设计还是商业考虑？
- Q5：链上积分如何实现"自动过期"？

### 2.5 Why（用户为什么要做这件事）

推断（来自之前对话）：
- 帮中小商家建立客户忠诚度（单家做不到规模）
- 通过"联盟"放大单家流量（A 家客户因为 B 家积分而来消费）
- 与 Mycelium 协议层目标对齐（非营利协作基础设施）
- 与 FangPay 共享商家网络（同一批 ICP）

### 2.6 How（用户已观察到的机制）

用户提到的关键机制：
1. **联盟内才能换**（不开放给全市场）
2. **兑换结果限定用途**（如换机票抵扣，不能套现）
3. **有时效**
4. **共同积分服务公司**（如 Star Alliance Services GmbH）做账目记录和结算
5. **双向收支记账**（A 公司收了 X 积分 / 支出 Y 积分）
