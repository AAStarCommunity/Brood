## 1. 三个核心判断

### 判断 1：跨商家积分**不是无解**，但**没有创新的法律空间**

经过 [CASE_STUDIES](./CASE_STUDIES.md) 和 [LEGAL_COMPLIANCE](./LEGAL_COMPLIANCE.md) 双重检验：

- 航空联盟运行 27 年，证明"跨商家积分 + 双边账本 + 法币 B2B 结算"模式**法律稳定可用**
- 加密圈过去 10 年的实验（Loyyal / Reddit / StepN / Blackbird）**没有走出新的法律边界**
- 唯一被监管认可的，是**保守地复制航空联盟**，再用链上账本做技术升级

→ **"我们能不能搞个新模式"** 的答案是：**新模式 = 旧法律框架 + 新技术实现**

### 判断 2：链上账本是**合规盟友**，不是敌人

直觉上"上链 = 麻烦"，但实际相反：

- 链上账本 100% 透明 → 监管随时可审 → **比传统 SaaS 还容易合规**
- 智能合约可强制时效、可强制兑换权限制、可强制不可转账 → **比代码合规的人工合规更可靠**
- 用户钱包自持积分 → 联盟方不持有 → **天然避开"支付机构"定性**

前提是按 [LEGAL_COMPLIANCE §10](./LEGAL_COMPLIANCE.md#10-给本研究的硬约束设计阶段必须遵守) 的 10 条硬约束设计。

### 判断 3：中国大陆 — 看具体模式（2026-06-22 修订）

⚠️ **原判断"不做的市场"过严**。用户咨询德勤反馈后重新调研，**区分两种模式**：

| 模式 | 中国可做？ | 推荐 |
|:---|:---:|:---|
| **A. 积分商城（B2B2C）** | ✅ 可做，无须 license | ⭐ 中国市场主推 |
| **B. 跨家直接互换（航空联盟）** | ❌ 几乎不可做 | 海外主推 |
| **C. 链上跨家代币** | ❌ 9·4 公告 + 跨家双红线 | 永不做 |

**修订后的现实结论**：
- **中国大陆**：做模式 A 积分商城（用传统 web2 栈，无须加密技术）
- **海外**：做模式 B 跨家联盟（用加密 / 链上技术差异化）
- **两线并行**：同一组商家在不同市场用不同产品形态

详细分析见 [CHINA_REALITY_CHECK.md](./CHINA_REALITY_CHECK.md)。

## 2. 为用户问题的直接回答

> 用户原问："那他这背后的账目怎么做，怎么合法，怎么合规，我其实不是太了解。"

### 2.1 账目怎么做

**双层账本**：
1. **链上事件账本** — 每笔积分发行/转移/兑换都 emit Event，永久不可篡改
2. **链下双边轧差账本** — 联盟 Worker 订阅链上事件 + 维护"商家 A 欠商家 B 累计 $X"

每月底：联盟账本生成结算建议 → 商家间用 USDC（或法币）B2B 结算 → 链上记录结算交易。

### 2.2 怎么合法

**核心 7 个特征**（来自 [CASE_STUDIES §7](./CASE_STUDIES.md#7-跨案例总结合规跨商家积分的-7-个共性特征)）：

1. 每家商家**自己发行**积分（不是联盟统一发币）
2. 联盟运营方**不持有**用户积分余额
3. 用户视角"我有 N 积分来自 X 家" → 联盟做**双边账本撮合**
4. 兑换**结果限定用途**（商家具体商品/抵扣券）
5. **不构造二级市场**（Soulbound NFT / ERC-1155）
6. 有**时效**（智能合约层强制）
7. 商家间**法币 B2B 结算**（USDC 链上或传统法币）

### 2.3 怎么合规

**操作清单**（[LEGAL_COMPLIANCE §11](./LEGAL_COMPLIANCE.md#11-实务建议)）：

上线前：
- 律师函 ≥ 3 份（US / EU / SG）
- 中国大陆完全屏蔽
- 完整 ToS（"积分非现金、限定用途、可作废、有时效"）
- 隐私政策（GDPR + CCPA + PDPA）

持续：
- 每年律师函重新审查
- 监控用户行为（防止打折转让 → 二级市场）
- 监控链上（积分若被挂 OpenSea → 立即下架）

应急：
- 合约保留 admin 冻结权限（应监管要求）
- DAO 治理可改规则
- 项目终止时：商家在 X 个月内允许用户兑换完毕

## 4. 与 Mycelium 协议哲学的对齐验证

| Mycelium 原则 | 方案 B 体现 |
|:---|:---|
| **数字公共物品** | 联盟合约 + 账本 Worker 全开源（Apache 2.0） |
| **零数据剥削** | 联盟方仅看 tx hash + 商家间账目，不看商品/用户身份 |
| **资金主权** | 商家自持私钥；积分在用户智能账户里；联盟方不过手 |
| **意义经济** | 帮中小商家形成"联盟网络效应"，对抗集中化平台 |
| **两层成本** | 运营 = 联盟入网费 + 链上 gas 抽成；规模 = HyperCapital 服务包 |
| **协议层不抽租** | 联盟只抽技术服务费，不抽商家商品销售额 % |
| **开源 + 商业双生** | L0 协议 (开源) vs L2 HyperCapital (商业服务) |
| **独家授权有期限** | HyperCapital 三年期 + 三年后社区投票引入竞争 |

## 5. 我的思考（Claude 视角，可能片面）

### 5.1 这件事**值得做**的理由

1. **中小商家的真痛点**：单店发积分用户感知极低；联盟积分能让"麦当劳客户去星巴克消费"，是真增长引擎
2. **加密圈缺好案例**：Blackbird 是少数成功案例（餐饮联盟），但大部分加密积分项目失败于"想做币" → Brood 模式（不发币）有差异化优势
3. **与 FangPay 协同极强**：同一批商家、同一套底层基础设施（AAStar）、同一个商业服务实体（HyperCapital）
4. **Mycelium 哲学的完美应用**：不抽租、不过手、不发币 → 三个"不"刚好对应三个最严监管红线

### 5.2 这件事**容易失败**的理由

1. **网络冷启动难**：联盟要 10 家以上商家才有价值，但前 9 家加入时无价值 → 需要**强力 onboarding + 商业服务包补贴**
2. **双边汇率谈判复杂**：N=20 时需要 190 个双边协议 → **HyperCapital 必须做标准模板 + 法务批量处理**
3. **商家不懂"为什么用区块链"**：传统积分系统 SaaS 已经存在 → 必须用 **gasless + 数据主权 + 跨家网络效应**三点差异化卖出去
4. **法务投入大**：律师函 + 持续监管沟通 + 每年审查 → 至少 $50k/年成本
5. **中国大陆心理预期**：很多商家会问"国内能用吗" → 必须诚实回答"不能，建议海外用户"

### 5.3 我的"如果只能给一个建议"

> **不要现在做方案 B**。
>
> **先做方案 A（task-2 Cos72 Lite + AAStar OpenPNTs）跑通 3-5 个真实商家 6 个月。**
> **6 个月后如果这些商家自发问"能不能跟其他家互通"** → **再启动方案 B 试点**。
>
> **如果没人问，说明"联盟"是设计师的幻想而非用户需求，省下钱不要做。**

理由：
- 联盟价值是**涌现的**，不是设计的
- 你不能"教育"商家"你需要联盟" → 必须让商家**自发产生联盟需求**
- 6 个月单店运营足以验证最小循环（发 + 用 + 兑）
- 验证之后扩到联盟是水到渠成；不验证就做联盟，等于在沙上盖楼

### 5.4 与 FangPay 的关系

FangPay 解决**新客获取**（"我能收加密")；
Loyalty Network 解决**老客复购**（"我能让客户回来 + 跨店增长")。

**两者应该是同一批 ICP，同一个商业服务实体（HyperCapital），同一个底层 (AAStar) ，但产品独立上线，分阶段做。**

### 5.5 关于"清算服务公司"角色

用户问到的"星空联盟有一家共同积分服务公司"是核心 — 这就是 **HyperCapital 的最大商业机会**：

- 不是支付机构（不接触资金）
- 不是积分发行人（不发币）
- 而是**技术服务 + 撮合账本 + 商业咨询**的综合服务商
- 收：年费 + 按笔技术费 + 月度运维包 + 一次性 onboarding
- 角色对应 PGL "Seller" 角色（平台运营佣金 10%）

这跟 Mycelium 双生模型（"开源 + 唯一授权商业实体"）**完美匹配**。
