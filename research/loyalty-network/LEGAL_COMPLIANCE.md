## 1. 核心法律问题：积分到底是什么？

任何积分系统都会被监管机构归入下列 4 类之一（或交叉）：

| 类 | 定性 | 监管态度 | 典型例子 |
|:---:|:---|:---|:---|
| **A** | 折扣返还 (Loyalty Reward) | 宽松，一般无须牌照 | 麦当劳积分换汉堡 |
| **B** | 预付凭证 (Stored Value) | 中-严，多数国家需牌照 | Starbucks Gift Card |
| **C** | 货币替代品 (E-money) | 严，需 EMI / 支付机构牌照 | PayPal 余额 |
| **D** | 证券 (Security) | 最严，需证券牌照 + 信息披露 | 收益权代币 |

**滑坡风险**：每往下走一级，定性发生时**整个产品形态都被否定**。

### 1.1 滑坡触发条件（重要）

| 触发条件 | 从 → 滑到 | 严重度 |
|:---|:---|:---:|
| 跨多家可流通 | A → B | 高 |
| 可累积、可兑换实物商品 | A → B | 高 |
| 可兑换现金 / 等价数字资产 | B → C | 极高 |
| 有二级市场 / DEX 交易 | C → D | 极高 |
| 有"持有升值期待" | C → D | 极高 |
| 联盟方持有用户积分余额 | A → B | 中 |
| 永不过期 | A → B | 中 |

## 2. 美国（US）

### 2.1 联邦层面

- **Howey Test**（证券定性，SEC v. Howey 1946）：
  - 投入金钱 + 共同事业 + 期待收益 + 收益来自他人努力
  - 商业积分**通常不满足**"期待收益"
  - **但**若有二级市场 + 升值期待 → 可能落入

- **FinCEN MSB** (Money Services Business)：
  - 若积分可兑换现金 → 属"money transmission" → 需 MSB 注册 + 各州牌照
  - 若仅兑换商品/服务 → 一般豁免

### 2.2 州层面

- **加州 CFL** (Cal. Financial Code §§17000): 多用途预付卡需 Money Transmitter License
- **纽约 BitLicense**: 涉数字资产时
- **德州、佛州**：相对宽松

### 2.3 安全边界

✅ **不踩线**：
- 单家积分（loyalty reward）
- 跨多家可流通，但**仅兑换商品/服务，不兑现金**
- 不在二级市场流通
- 联盟运营方仅做技术服务

⚠️ **风险**：
- 跨多家积分 + 可累积 + 兑换标准化商品 → 部分州可能要求 Money Transmitter
- 一旦"上 DEX 可交易" → SEC 高度关注

### 2.4 参考案例

- 航空里程：从未被 SEC 起诉
- StepN 等 Move-to-earn：SEC 持续调查
- Reddit Notes / Coinbase Earn：边谈边调

## 3. 欧盟（EU）

### 3.1 主要法规

- **E-Money Directive 2009/110/EC** (EMD2)
- **MiCA Regulation** 2023/1114（2024 起分阶段生效）
- **PSD2** (Payment Services Directive)

### 3.2 MiCA 下三种代币

| 类型 | 定性 | 是否监管 |
|:---|:---|:---|
| **Asset-Referenced Token (ART)** | 参考多种资产 | 需 MiCA 牌照 |
| **E-Money Token (EMT)** | 1:1 对应法币 | 需 EMI 牌照 |
| **Utility Token** | 仅给予服务/商品访问权 | **豁免 MiCA**（但需白皮书） |

### 3.3 安全边界

✅ Utility Token 路线：
- 积分 = 仅访问服务（兑换商品）
- 不可兑换法币
- 不参考资产价格
- 完整白皮书 + 风险披露

⚠️ 风险：
- 一旦跨多家 + 标准化兑换比率 + 可流通 → 可能被认定为 EMT
- 联盟运营方做"账本" + 资金过手 → 触发 EMI

### 3.4 PSD2 角度

- 若联盟运营方为商家"代收代付"现金 → 支付机构（PI）牌照
- **不过手资金** → 一般豁免

## 4. 新加坡（SG）

### 4.1 主要法规

- **Payment Services Act 2019 (PSA)**
- **MAS Notice on Digital Payment Token (DPT)**

### 4.2 PSA 下监管的活动

PSA 把"支付服务"分 7 类，与积分相关的：
- **E-money Issuance** — 发预付价值
- **Domestic Money Transfer** — 国内转账
- **Digital Payment Token Service** — 数字代币交易

### 4.3 Limited Purpose Digital Payment Token 豁免

MAS 给出明确豁免：
> "Limited Purpose DPT" = 仅用于支付特定商家商品/服务，不可兑换法币、不上交易所

→ **商业积分若严格限定用途，可获豁免**

### 4.4 安全边界

✅ 与 EU MiCA Utility Token 路线类似

⚠️ 注意：
- SG MAS 对"跨商家流通"特别敏感
- 建议联盟内 < 100 家商家，避免被认定为"通用电子货币"

## 5. 中国大陆 ⭐ 用户特别关心

> ⚠️ **2026-06-22 修订**：本节原版判断**过严**。用户咨询德勤同学后反馈"积分商城在中国无须 license"，经过重新调研，确认**积分商城模式（B2B2C 礼品采购）确实在中国大陆可做且广泛运营**。完整修订见 [CHINA_REALITY_CHECK.md](./CHINA_REALITY_CHECK.md)。本节保留原文作为"跨家直接互换模式"的法律分析，但**不适用于"积分商城模式"**。


### 5.1 主要法规

- **《非金融机构支付服务管理办法》** (人行 2010 第 2 号令)
- **《支付机构预付卡业务管理办法》** (人行 2012 第 12 号公告)
- **《商业预付卡管理办法》** (商务部 2012 第 9 号令)
- **2017 "9·4 公告"** —— 禁止 ICO + 代币交易
- **2021 "9·24 通知"** —— 进一步收紧虚拟货币

### 5.2 关键分类

中国把预付凭证分两类：

| 类 | 定义 | 监管 |
|:---|:---|:---|
| **单用途预付卡** | 仅在发行商家使用 | 商务部备案，相对宽松 |
| **多用途预付卡** | 跨发行人使用 | **人行预付卡牌照** + 100% 备付金 |

**红线**：未经人行批准，**任何机构和个人都不能发多用途预付卡**。

### 5.3 跨商家积分 = 多用途预付卡？

实务认定标准（来自人行 / 央行处罚案例）：
1. **可跨发行人使用** ✓
2. **可累积** ✓
3. **可兑换标准化商品/服务** ✓
4. **有等价货币定价** ✓ ← 这一条是关键

→ 满足上述 4 条 → **几乎一定被认定为多用途预付卡**

### 5.4 历史处罚案例

| 案例 | 时间 | 处罚 |
|:---|:---|:---|
| 上海某美容连锁跨店通用卡 | 2015 | 罚款 + 退款 |
| 某教育培训跨校区积分 | 2017 | 整改 |
| "积分宝"P2P 交易 | 2018 | 全部下线 |
| 几个区块链积分项目 | 2017 9·4 | 全部停止 |

### 5.5 中国合规路径（如果一定要做）

> ⚠️ 路径 1-3 都极难，**实务上建议直接放弃中国大陆市场**

| 路径 | 难度 | 说明 |
|:---|:---:|:---|
| 1. 申请预付卡牌照 | 极难 | 资本金 1 亿+、央行严格审批，2016 年后基本停发 |
| 2. 与持牌支付机构合作 | 难 | 找银联 / 银行 / 支付宝合作，他们做发行人 |
| 3. 限制为单商家积分 | 易 | 但失去"联盟"价值 |
| 4. 海外注册主体 + 中国大陆不开通 | 中 | IP 屏蔽 + ToS 拒绝 |

### 5.6 中国大陆现实结论（2026-06-22 修订）

⚠️ **原结论"几乎一定不合规"过严**。重新调研后区分两种模式：

| 模式 | 中国可做？ | 说明 |
|:---|:---:|:---|
| **A. 积分商城（B2B2C 礼品采购）** | ✅ **可做，无须特殊牌照** | 平台运营商城，单家商家积分仅在该商城使用；类似京东企业购 / 福利易 / 招行积分商城 |
| **B. 跨家直接互换（航空联盟）** | ❌ 几乎不可做 | A 家积分直接到 B 家门店消费 = 多用途预付卡定性 |
| **C. 链上代币 + 跨家流通** | ❌ 9·4 / 9·24 公告红线 | 链上代币 + 跨家 = 双重监管风险 |

**模式 A 详细合规要点见 [CHINA_REALITY_CHECK.md §3-4](./CHINA_REALITY_CHECK.md#3-积分商城在中国怎么合规做参考成熟案例)**

✅ **可行路径（更新）**：
- **方案 1（中国）**：模式 A 积分商城（传统 web2 栈，无须加密技术）
- **方案 2（海外）**：模式 B 跨家联盟（加密 / 链上技术差异化）+ IP 屏蔽中国大陆
- **方案 3（两条线并行）** ⭐ 推荐：中国市场做模式 A，海外做模式 B

## 6. 联盟运营方 / 清算服务方的法律定性

> 用户问到："共同积分服务公司" 是什么角色？需要什么牌照？

### 6.1 三种可能定性

| 定性 | 触发条件 | 监管 |
|:---|:---|:---:|
| **A. 技术服务商** | 仅提供账本、撮合、API | 一般无须牌照 |
| **B. 支付机构** | 接触资金 / 代收代付 | 需支付牌照 |
| **C. 发行人** | 自己发行积分 | 视积分定性 |

### 6.2 安全设计（让自己落入 A）

参考 Star Alliance Services GmbH 模式：

✅ **可以做**：
- 维护账本（链上 + 链下）
- 提供 API、SDK、文档
- 处理双边轧差账目
- 收取技术服务费

🚫 **不能做**：
- 持有用户积分余额
- 持有商家结算资金
- 自己发行任何"通用积分"
- 充当资金中间方

### 6.3 收费模式

| 模式 | 合规度 | 例子 |
|:---|:---:|:---|
| 按笔抽 % | 中（容易被认定"支付费率"） | 信用卡刷卡费 2% |
| 按笔固定服务费 | 高 | $0.05 / tx |
| 月度订阅 | 高 | $99 / 商家 / 月 |
| 链上 gas 抽成 10% | 高 | FangPay 模式 |
| 商家会员费 | 高 | 联盟会员费 $X / 年 |

**推荐**：月度订阅 + 按笔固定服务费（避免被认定为支付佣金）

## 7. 跨境流通的特殊问题

### 7.1 用户跨境

- 中国用户在新加坡使用 → 中国监管视为"境外服务"，一般不管（除非涉外汇）
- 新加坡用户在中国商家积分账户 → 中国监管视为境内积分

### 7.2 商家跨境

- 中国商家加入海外联盟 → 中国监管严格（外汇 + 跨境支付）
- 海外商家加入跨国联盟 → 各国分别合规

### 7.3 涉外汇 / 跨境结算

- 联盟内法币 B2B 结算 → 跨境时触发外汇管制
- 建议**用 USDC 等稳定币结算**（链上、可审计、避免银行外汇问题）
- 但中国大陆商家无法用 USDC 收款（外汇红线）

## 8. 链上 / 加密积分的合规优势 vs 劣势

### 8.1 优势 ✅

| 优势 | 解释 |
|:---|:---|
| **链上账本透明** | 监管可随时审计每笔积分发行/转移/销毁 |
| **不可篡改** | 防止商家私自改账 |
| **自动时效** | 智能合约可强制过期 |
| **无统一发行人** | 每家商家发自己代币，避免"联盟代币"定性 |
| **不可现金兑换** | 智能合约可锁死兑换路径 |
| **可撤回设计** | smart contract upgrade 可应监管要求改规则 |

### 8.2 劣势 ❌

| 劣势 | 解释 |
|:---|:---|
| **二级市场风险** | 即使协议不上 DEX，链上代币可能被人挂去 Uniswap |
| **合规判例少** | 监管对"链上积分"分类经验不足 |
| **跨境数据流动** | 链上数据无国界，触发 GDPR / 中国《数据安全法》 |
| **钱包地址 = 身份** | 链上分析公司可反推用户 |

### 8.3 关键合规设计技巧

为了享受链上优势同时规避劣势：

```
1. 积分合约用 "Soulbound" 模式 (Non-transferable ERC-721/ERC-1155)
   → 链上无法转账给其他用户 → 不可能形成二级市场

2. 兑换权由商家智能合约控制
   → 用户只能 "burn 积分 + 收商家发的兑换券"
   → 不存在"积分 vs 现金"的 swap 接口

3. 时效在合约层强制
   → expiresAt 字段，到期自动作废
   
4. 用户身份用 AirAccount + Passkey
   → 链上地址 = AirAccount，不直接关联现实身份
   → 商家看不到用户的其他钱包

5. 联盟账本用 Merkle Tree
   → 商家间互相 verify 账目，无须信任清算方
```

## 10. 给本研究的硬约束（设计阶段必须遵守）

> 任何方案违反下列任一条 → **不通过**

| # | 硬约束 | 违反则触发 |
|:---:|:---|:---|
| 1 | 不发行可在 DEX 自由交易的代币（用 Soulbound 或限制 transfer） | SEC 证券调查 |
| 2 | 不允许积分兑换法币 / 等价稳定币 | E-money 牌照需求 |
| 3 | 联盟方不持有用户积分余额（积分在用户智能账户里） | 支付机构定性 |
| 4 | 兑换结果限定为"商家提供的商品/服务" | 通用支付工具定性 |
| 5 | 积分必须有时效（推荐 90 天-2 年） | 永久价值储存 |
| 6 | 不在中国大陆运营或提供服务（IP 屏蔽 + ToS 拒绝） | 中国预付卡红线 |
| 7 | 联盟方收费用"技术服务费"模式（不抽交易 %） | 支付佣金定性 |
| 8 | 商家间结算用 USDC 等稳定币（链上透明）或法币 B2B（合同清晰） | 资金混同 |
| 9 | 商家入网协议明确"积分非证券、非货币、限定用途" | 法律抗辩证据 |
| 10 | 律师函覆盖 US + EU + SG 至少 3 个市场 | 国际经营底线 |

## 11. 实务建议

### 11.1 上线前必做

1. **律师函 ≥ 3 份**（US / EU / SG）确认"非支付机构、非证券"定性
2. **中国大陆完全屏蔽**（IP 地理围栏 + ToS 明确拒绝）
3. **完整 ToS** 包含"积分非现金、限定用途、可作废、有时效"
4. **隐私政策** 符合 GDPR + CCPA + 新加坡 PDPA

### 11.2 持续监控

- 每年律师函重新审查（监管在演化）
- 监控用户行为：若发现大量"打折转让"积分 → 暂停该商家
- 监控链上：若发现积分被挂 OpenSea / Uniswap → 立即下架

### 11.3 应急方案

- 智能合约保留"协议管理员可冻结某商家"权限（应监管要求）
- DAO 治理可投票更改规则（响应法规变化）
- 用户积分应急对接：若项目被叫停，让商家在 X 个月内允许用户兑换完毕

## 12. 一句话

> **跨商家积分在 US/EU/SG 有"灰区合规路径"（限定用途 + 不可现金 + 不可二级市场 + 有时效 + 律师函）。**
> **中国大陆几乎不可能合规，建议完全屏蔽**。
> **链上账本是合规的盟友（透明可审计）而非敌人**，前提是按硬约束 §10 设计。
