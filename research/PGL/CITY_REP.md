# CityRep · 城市声誉网络
# City Reputation Network — A Mycelium-level extension of AgentStore

> 版本：v0.1（构想阶段） · 最后更新：2026-05-15
> 状态：**RFC / 探索性文档**，等待真实城市试点验证
> 定位：**不是 AgentStore 的一部分**，是基于 AgentStore + Mycelium Protocol 自然延伸出来的「下游网络」

---

## 1. 是什么 / 不是什么

### CityRep **是**

一个**去中心化的城市声誉网络**：当大量个体用户和中小组织在 AgentStore 的统一账户体系（AirAccount）下使用「数字公共物品」（PGL 作品）并产生**真实可验证的行为记录**时，这些记录自然汇聚成一张**城市与人的协作信任网络**，使城市可以基于事实而非宣传积累声誉。

### CityRep **不是**

- **不是 AgentStore 内置功能** —— AgentStore 只提供账户、公物、记录三块基础设施
- **不是法律意义上的股东 / 股权** —— "虚拟股东"只是隐喻，不发任何代表所有权的代币
- **不是中心化平台**（如 TripAdvisor / 大众点评）—— 没有运营方可以删评、屏蔽、卖竞价排名
- **不是必须接入** —— 城市自愿，居民自愿，旅行者自愿

## 2. 核心机制

### 2.1 一句话原理

> **真实行为 → 链上记录 → 可被多方对比、AI 分析、相互 argue → 事实沉淀为城市声誉。**

整个机制不依赖中心化裁决，依赖**多源记录的可比性**和**事实的自洽性**。

### 2.2 一个旅游城市的例子

```
[ 旅行者 Alice 来某城旅游 ]
       │
       │ 使用 PGL 公物：旅游笔记 agent、本地推荐 agent、消费记账 agent
       ▼
[ 行为记录上链 ]
   - 在哪里吃了什么、花了多少（消费记账 agent）
   - 拍了哪些照片、走了哪些路线（旅游笔记 agent）
   - 对哪些景点/店家给出真实评价（评价 agent）
       │
       ▼
[ 同期其他几百位旅行者也产生类似记录 ]
       │
       │ 多源记录可被相互对比、AI 交叉分析
       ▼
[ 共识事实沉淀 ]
   - "X 餐厅性价比好" 被 80% 真实消费过的人确认
   - "Y 景点收费虚高" 被 60% 实测者标记
   - "Z 街区夜晚不安全" 在 30 起记录中浮现
       │
       ▼
[ 城市基于真实事实积累声誉 ]
   - 不依赖政府宣传
   - 不依赖运营方算法
   - 经得起反驳与对比
       │
       ▼
[ 反馈循环 ]
   - 新旅行者基于真实声誉决策
   - 好城市持续吸引人，差区域被诚实暴露
   - 旅行者作为「贡献者」获得回馈
```

## 3. 真实性如何保证

声誉网络的命门是**反伪造、反 Sybil、反操纵**。CityRep 用三层防御：

### 层 1 · 账户成本（基础门槛）

- 每条记录必须由 AirAccount 签发
- AirAccount 注册需要 passkey / 真实设备 / 真实邮箱
- 一人多账号成本高但非不可能 → 不是绝对防御，是过滤层

### 层 2 · 多源交叉验证（核心防御）

- 同一时空内多人记录可对比
- 单条好评 → 弱信号
- 几十条独立账户产生的、含细节的、时间错开的好评 → 强信号
- AI 分析检测异常模式：写作风格相似度、时间集中度、消费金额异常、地理轨迹冲突

### 层 3 · 公开 argue（事后纠错）

- 任何人可以挂出"反驳证据"
- 反驳本身也是链上记录
- 长期来看，**说真话的人在统计上获胜**（因为真相不需要协调）
- 类似 Wikipedia 的编辑战机制，但带链上签名

**关键设计哲学**：CityRep 不追求每条记录的真假判定，**追求大量记录的统计真相**。少数虚假记录会被多数真实记录稀释和修正。

## 4. 「虚拟股东」机制详解（避开证券合规雷区）

用户提到「真实贡献者像是城市的虚拟股东」—— 这是个很好的隐喻，但**不能法律上是股东**，否则触证券监管。所以我们的设计是**强化版的引流分成**：

| 维度 | 传统股东 | CityRep 贡献者 |
|:---|:---|:---|
| 法律属性 | 股权 / 证券 | 推荐分成 / 引流奖励 |
| 持有什么 | 股票 / 股份 | 贡献度记录（SBT，不可转让）|
| 收益来源 | 公司利润分红 | 商家自愿支付的引流佣金 |
| 收益形式 | 现金股息 | 旅游折扣、当地特权、xPNTs 积分（可消费）|
| 是否上市/交易 | 可在二级市场交易 | **不可交易**（SBT 不可转让） |
| 投票权 | 股东大会 | 无（如有治理权，走 DAO 而非"股东"框架） |
| 监管定性 | 证监会管辖 | 普通商业合同 / 营销活动 |

具体回馈形态举例：

| 贡献行为 | 即时回馈 | 长期回馈 |
|:---|:---|:---|
| 写一篇真实游记被 AI 验证 | 0 | 贡献度 SBT +1 |
| 你的游记被 N 个新游客在出行前查看 | 引流分成（商家广告预算 × 引流权重） | 推荐者 SBT 强化 |
| 你的游记直接带来 M 个真实订单 | 订单引流分成 | 长期推荐者特权（折扣等） |
| 你举报了一条虚假评价并被验证 | xPNTs 奖励 | 监督者 SBT +1 |

**核心特点**：
- 没有"先付钱买股权"的环节（不是众筹，不是证券）
- 回馈和**真实可验证的引流效果挂钩**（不是空气）
- 所有回馈都是商业语境下的**正常营销支出**（广告费、推荐佣金、营销折扣）
- 数据透明上链，但不发行可交易的"股权代币"

## 5. 角色生态

| 角色 | 在 CityRep 中做什么 |
|:---|:---|
| **个体贡献者**（旅行者/居民） | 用 PGL 公物产生真实行为记录，累积贡献度 |
| **本地商家**（餐厅/景点/民宿） | 接收真实评价；可设置自愿引流分成池吸引推广 |
| **中小组织**（旅游公司/媒体） | 基于真实声誉做服务推荐，按引流抽佣 |
| **城市治理者**（文旅局/街道办） | 基于真实记录优化公共服务，引导预算流向真问题 |
| **公物作者**（PGL 签约者） | 持续优化公物 agent，从 AgentStore 分账中获益 |
| **DAO 治理者** | 制定记录规范、仲裁争议、维护反伪造算法 |

## 6. 与现有 Mycelium 生态的关系

```
┌──────────────────────────────────────────────────────────┐
│                     CityRep（本文档）                      │
│             城市声誉网络（语义/经济/社会层）                │
├──────────────────────────────────────────────────────────┤
│  CityOS（已规划） · 公共服务 agent 池 · 城市级编排          │
├──────────────────────────────────────────────────────────┤
│  AgentStore + PGL · 公物分发 · 账户 · 链上记录             │
├──────────────────────────────────────────────────────────┤
│  SuperPaymaster v5 · AirAccount · OpenPNTs · CometENS    │
├──────────────────────────────────────────────────────────┤
│            Park · Spores · OpenPNTs（协议层）              │
└──────────────────────────────────────────────────────────┘
```

CityRep 是**最上面的语义/经济层**，自然继承下面所有层的能力：
- AirAccount → 身份基础
- AgentStore + PGL → 行为产生与记录基础
- CityOS → 公共服务编排（暂未落地）
- SuperPaymaster + xPNTs → 价值结算
- Park 协议 → 公物治理基础

## 7. 与 AgentStore 的关系（重要边界）

| 维度 | AgentStore | CityRep |
|:---|:---|:---|
| 性质 | 分发渠道 + 商业基础设施 | 社会经济网络 + 声誉系统 |
| 主体 | Mycelium DAO 运营 | 各城市/社区自治 |
| 主要参与方 | 作者 + 用户 | 用户 + 商家 + 城市 + 治理者 |
| 收入模式 | 软件销售分成（10% 渠道佣金） | 引流分成 + 广告 + 推荐佣金（与 AgentStore 解耦） |
| 是否必须 | PGL 必须 | 城市自愿采用 |

**关键边界**：AgentStore **不应当**为了拉拢城市而强行嵌入 CityRep 机制。CityRep 是**自然涌现的下游**，不是 AgentStore 的功能模块。AgentStore 只保证「真实行为可被记录」，CityRep 在此之上做语义解读和经济激励。

## 8. 我们能力的边界（诚实声明）

### 我们能做：

- 提供账户体系（AirAccount）
- 提供记录基础设施（链上不可篡改）
- 提供公物分发渠道（AgentStore + PGL）
- 提供价值结算（SuperPaymaster + xPNTs）
- 提供 DAO 治理工具

### 我们做不到（也不该做）：

- **替城市做声誉判定** —— 真假是城市内部和参与者的事
- **保证 100% 反伪造** —— 任何系统都有作弊空间，我们只能降低成本不能根除
- **强迫商家接受真实评价** —— 商家可以选择不参与
- **替代政府监管** —— 食品安全、消防、治安等监管职责不在我们范围

## 9. 试点路径

### 阶段 1 · 选种子城市（2026 Q3-Q4）

候选条件：
- 中等规模旅游城市（人口 50-200 万）
- 有数字化基础（智慧城市试点最佳）
- 地方政府/文旅有创新意愿
- 本地有 1-2 个 Mycelium 生态社区站点

### 阶段 2 · 基础公物部署（2027 Q1）

至少 5 个 PGL 公物 agent 上线：
- 旅游笔记 agent
- 消费记账 agent
- 真实评价 agent
- 本地推荐 agent
- 商家引流 agent

### 阶段 3 · 城市声誉沉淀（2027 全年）

- 至少 10,000 条真实记录
- 至少 50 家本地商家接入
- 至少 1 个跨年对比报告（"上海 vs 杭州，谁的旅行者满意度高？"基于真实数据）

### 阶段 4 · 跨城对比（2028+）

- 多城接入后形成对比基线
- AI 跨城分析，产出年度报告
- 真正的"用脚投票"基础设施

## 10. 开放问题（等待讨论）

1. **「贡献度 SBT」** 是发给个人还是发给作品/行为？
   - 个人方便累积，但隐私问题
   - 行为粒度可隐私化，但难累积
2. **商家引流分成池** 怎么设计才能避免类似"互联网医疗"的医生回扣丑闻？
3. **"反向声誉"**（负面记录）的法律风险（诽谤）怎么管？
4. **跨城旅行者** 的记录在 Source City 和 Destination City 如何分配权重？
5. **小众场景**（小语种地区、少数民族文化区）怎么避免被主流声誉算法稀释？

这些问题不在 Phase 1 解决，留待真实试点中迭代。

## 11. 命名说明

- **CityRep** = City Reputation Layer（城市声誉层）
- 不叫 "CityScore" / "CitySocial"，因为不想引入"社会信用"那套联想
- 不叫 "CityDAO"，避免与已有 CityDAO 项目冲突
- **Rep** 取自 Reputation，简洁且与 GitHub repo / reputation 双关
